# NATIVE — the native app's page holds NO GPU state

Goal (Pascal 10-10): in the native app (Tauri/wgpu, Metal) every draw + every GPU compute runs in `gaia-render`; the JS page keeps the scene graph, TSL *node graphs*, CPU bookkeeping — and **no GPU device, buffer, texture or pipeline**.
Measured 10-10 (browser, `renderBackend=wgpu`): three's `WebGPURenderer` device in the GPU process grew ~20 MB/s and duplicated every resource the wgpu core also held.

## §three-gpu — inventory of three's GPU use in `renderBackend=wgpu` (lane nt-gi, base 34ff6fd7)

Flag: **`?renderBackend=native`** (nt-host/nt-ipc: draw via `GaiaRenderNative` IPC → Rust `gaia-render-host`) implies it. For the browser A/B: `?renderBackend=wgpu&threeGpu=0` (or `window.__GAIA_NATIVE__ === true`). Code: `client/kernel/render-api/native-mode.js`.
**No GPU context of any kind** in the page (nt-host masks `navigator.gpu`, which would make `WebGPURenderer.init()` fall back to WebGL2 — so init must never run). Guarantees, in order: (1) `main.js` calls `installGpuContextGuard()` first thing for `renderBackend=native`: `HTMLCanvasElement/OffscreenCanvas.getContext('webgl'|'webgl2'|'webgpu'|…)` returns `null` and is counted in `globalThis.__gaiaGpuContextBlocked` (2d stays: CPU pixel reads). (2) `createRenderer({gpu:false})` never calls `init()` — the WebGL2 fallback lives only in `Renderer.init()` (`getFallback`), verified in three r180 `WebGPURenderer.js`/`Renderer.js`: the constructor builds the backend object and a bare `<canvas>` (`backend.getDomElement()`), no context. (3) `lockThreeGpu` makes every lazily-initing/GPU entry point a counted no-op. (4) the wasm module + overlay canvas are not used (`gaia-render-native.js`); `gpu-mirror` is not installed.
Effect: `createRenderer({gpu:false})` (kernel/renderer.js) constructs the `WebGPURenderer` but **never `init()`s it** (three r180: `WebGPUBackend.init` is the only adapter/device request; the constructor, `setSize`, `toneMapping`, `shadowMap` setters are device-free) and `lockThreeGpu()` turns every entry point that would lazily `init()` or run GPU work into a counted no-op (`renderer.userData.threeGpuBlocked = {method: calls}`, one console warning per method). `main.js` drives frames with rAF (three's `setAnimationLoop` would `init()`).
Default (no flag) = unchanged browser behaviour.

### What still runs on three's GPU in native mode
**Nothing** — by construction: no device exists. Features without a native path are *off* and counted in `renderer.userData.threeGpuBlocked`: fluid (#12), RTS-mode GI (#13), any game code calling `renderer.render/compute/readRenderTargetPixelsAsync` (e.g. `fluid-thickness`).

### Page-atlas contract (external extension, not in this repo)
`gpu-mirror.js` exists because an extension (the Paleblood atlas) writes streamed pages straight into three's `GPUTexture` through `renderer.backend.device.queue.writeTexture`. With no three device that path cannot exist. Minimal fix (extension side): keep such `DataArrayTexture`s CPU-backed — `texture.image.data` populated and updates flagged with `texture.addLayerUpdate(i)`/`needsUpdate`; `material-map.js arrayTextureData` (:85-99, non-mirror branch) already ships exactly that to the core (`updateTextureLayer`). UNVERIFIED against the extension.

## Native probe GI (what moved, how it is wired)
```
page (CPU only)                                   gaia-render (Metal)
GIOpen._updateNative  ─ giComputeInit(cfg JSON) ─► GiCompute::new  (voxel/ray/irr/depth buffers, 3 pipelines; depth := -1)
 voxel window bricks  ─ giComputeVoxels(start,u32[]) ► queue.write_buffer (voxels)
 cascade scroll/batch ─ giComputeStep(frame f32[44], fresh u32[]) ► depth sentinel writes + pending frame
                                                  render_frame → encode_forward → encode_gi_compute:
                                                    pass{ trace → irr_blend → depth_blend }, copy atlas buffers → 4096-wide textures
                                                    forward uniform written ONLY after the first batch is computed (no black-GI frames)
TSL materials: atlas attr tagged userData.nativeStorage → bindThreeStorage(reserved ids u32::MAX-1 / u32::MAX = the same atlas buffers)
```
* Algorithm = translation, not rewrite: `gi_compute.wgsl` mirrors `gi-open-raypar.js` (trace/irr/depth) and `gi-open-nodes.js` (`readVoxelTSL`, `marchVoxelsTSL`, `voxelNormalTSL`, `resolveProbeTSL`, `probeWorldPos`, `batchProbeIndex`, `queryCascadesTSL`, sky/fibonacci/octahedral). Deviations (all result-neutral): `break` instead of the TSL `go` guard in the march; the candidate-relocation reverse loop is a forward loop taking the first free; the bounce query reuses forward.wgsl's `gi_query` math (exact `pos_mod` instead of `CELL_BIAS`).
* Every tunable is config (`GIOpen.nativeConfig()` → JSON; Rust has no defaults, a missing key is a loud error): cascades, resolutions, rays, voxel window dims/cell/bias, march + relocate steps, maxDist, relocateMax, blendCells, hysteresis alphas, adaptive fast/threshold, golden angle. Frame array layout = `gi-native.js GI_FRAME` ↔ `gi_compute.rs GF_*`.
* Only the ray-parallel path exists natively (`rayParallel:false` legacy kernels throw loudly in native mode).
* Browser wgpu mode: unchanged (`gi-bridge.js` readback). `&wgpuGiNative=1` runs the native compute in a browser (wasm wgpu) for A/B (three then still owns a device, GI-wise idle). In `renderBackend=native` the bridge is never created (it would need `getArrayBufferAsync` on a device-less renderer).
* Wire (nt-ipc): `giComputeInit(cfgJson)`, `giComputeVoxels(start,u32[])`, `giComputeStep(f32[44],u32[])`, `giComputeDestroy()` are ordinary generated ops (render-wasm export → `Commands` trait → `Session`; `tools/gen-render-native.mjs` regenerated, api_hash `0xfcbc19dd`); `giComputeStats` ([steps, probes, voxelWrites, fresh, irrRows, depthRows, renderErrors]) is a generated query (value of the last frame report). Op errors come back in the IPC report (`gpu.errors`); render-time GI failures bump `renderErrors` and print once to host stderr. Reserved atlas storage ids are a wire constant: JS `gi-native.js GI_STORAGE` ↔ Rust `GI_STORAGE_IRR_ID/GI_STORAGE_DEPTH_ID` (u32::MAX-1 / u32::MAX; JS-minted ids start at 1).
* Follow-ups (not done): forward.wgsl could sample the atlas *buffers* directly and drop the 18.9 MB texture copy + per-frame buffer→texture copy (needs a fragment-stage storage-buffer budget check); batch the fresh-probe sentinel writes (a 30 m move = 2688 small `write_buffer`s).

### Writer-side backpressure (scene-adapter `encodeCapBytes`)
* `backend.pendingBytes()` = unflushed Writer + transport queued + in flight (serialized, not host-acked). `admit(bytes, kind)` false when pending > cap.
* Gates (all pre-flight, NO side effects → nothing half-built, retried next sync; counted in `adapter.stats.defer{objects,rebuilds,geometry,materials,skinned,batched,bytes}`):
  new Mesh/InstancedMesh object (`recCost`: new geometry parts + textures of not-yet-created materials not already on host via `backend.textureCached`) · rebuild · geometry re-upload · material texture edit (`convCost`) · new SkinnedMesh · new BatchedMesh group (batch stays dirty).
* Live pending contains what the same sync already encoded ⇒ overshoot ≤ ONE admitted object. `bytes ≤ 0` (all on host) always admitted. Not gated (small/rare): sprites, points, lights, matrix/instance updates, TSL-only texture bindings (invisible before export), cube/array textures, new materials of an admitted rec.
* Net: the scene streams in over frames at host-ack pace instead of being serialized in sync 1. Presenter `busy()` (queued > `busyMB`=8) still skips whole syncs first; cap is the second line for single big syncs.
### Post-ack release (OPT-IN — game-owned memory; default off)
* Mechanism: `GaiaRenderNative.afterAck(fn)` = run when host acked every byte written so far (stream offset mark vs `ackedBytes`; transport `onAck`). Wired: texture upload (`desc.release`), mesh create (`scheduleRelease`).
* Flags: `texture.userData.nativeRelease` / `geometry.userData.nativeRelease` (true|'all'|false) or global `?nativeReleaseSrc=1`.
  · texture: compressed → `mipmaps[i].data = empty` ; ImageBitmap → `close()` ; HTMLImageElement → `source.data = null`. DataTexture/canvas: never (dynamic, CPU systems write them).
  · geometry `true` → drop `normal`+`uv` arrays; `'all'` → also `position`+`index`.
* KEPT BY DEFAULT + why: geometry `position`/`index` (Mesh.raycast, collision, Box3/bounds, Points/Batched/Skinned rebuild read them) · `normal`/`uv` (re-upload after gc: object removed → mesh destroyed → re-added needs the arrays; cell streaming) · instanceMatrix/instanceColor arrays (mutated per frame by game, live-range views) · skinIndex/skinWeight/skeleton (palette every frame; skinned rebuild) · DataTexture/canvas pixels (game-written) · CubeTexture faces cache (`cubeCache`, few) · DataArrayTexture data (view, no copy) · material `conv` (params + small descs).
* Hazards (why opt-in): released source can never re-upload → geometry: `geometryArrays` refuses LOUD (`stats.unsupported`: geometry-arrays-released) ; texture: backend records `texture:…released…` in `stats.unsupported`, material draws untextured (never a thrown frame). Clones sharing the `Source`/`mipmaps` array lose it too. DS should flag: BC `CompressedTexture`s and static GLTF geometry that nothing raycasts.

* Fields (page): `ipc` = transport (`createTransport` stats): `tx_queued` bytes pushed not yet sent (page-held copies) · `tx_inflight` bytes/msgs sent not acked (= sent − acked) · `ws_buffered` = `WebSocket.bufferedAmount` (browser-side unsent; subset of inflight) · `wr_scratch` = Writer ArrayBuffer capacity (grow-only, never shrinks) · `wr_fill` current fill. `scene` (one `scene.traverse` per tick; `scan_ms` = its cost; root = `window.gaia.scene`): `tex_*` textures reachable from scene materials (any own texture prop + `uniforms[*].value`) ∪ textures the adapter shipped (`material-map.textureData` hook, WeakRef): `tex_data` real CPU bytes (DataTexture/ImageData `image.data`, deduped by ArrayBuffer), `tex_mip` `mipmaps[].data`, `tex_decodedEst` **ESTIMATE** w·h·4 of ImageBitmap/Image/canvas backing (WebKit gives no size). `geo_*` BufferAttribute/index/morph arrays, deduped by ArrayBuffer identity (`geo_MB` = unique buffers' byteLength, `geo_view_MB` = sum of view lengths; big gap = shared/oversized backing buffers). `inst`/`skin` = InstancedMesh matrix/colour, skeleton boneMatrices. `buf_<cat>` = buffers registered via `trackBuffer(cat, buf)` (weak): `pixelRead` = `readPixels()` RGBA copies held by material-map `pixelCache`/texture descs (the usual leak suspect), `vrm` = `fetchVrmBytes` cache. `tracked_total_MB` = sum of ipc(queued+inflight+scratch) + tex + geo + inst + skin + buf (one buffer counted once across categories).
* Fields (host): `gw_MB` = game-window `phys_footprint` (`proc_pid_rusage` RUSAGE_INFO_V0, = Activity Monitor "Memory"), `gw_rss_MB` resident. `wc_*` = WebContent process, same calls. WebContent is **NOT a child** of game-window (WebKit XPC service, parent launchd → `proc_listchildpids` useless); pid comes from private `-[WKWebView _webProcessIdentifier]`, refreshed by thread `gaia-memfoot` every `--page-mem-ms` (main-thread `with_webview`). `n/a(...)` shows why (SPI missing / pid not sampled yet / rusage errno). rusage on another same-uid pid verified readable (standalone check).
* How to read: `wc_MB` − `tracked_total_MB` = what the page does NOT account for (JS heap objects, decoded image caches, GC garbage, WebKit-internal). `tx_queued`+`ws_buffered` growing = host slower than page producing (backpressure not holding). `pixelRead` large = CPU RGBA copies pinned by texture descs. `geo_view ≪ geo` = oversized shared buffers. Compare consecutive lines: the category whose slope matches `wc_MB` is the leak.
* Params in ONE place: interval = `config.rs OPTIONS` row `page-mem-ms`; JS: `MEM_PARAMS` in `client/kernel/render-api/native/mem-account.js` (decoded bytes/pixel, line cap, log level, scene root getter). Registry: `register(name, fn→{k:v})` (keys ending `Bytes` print `_MB`, `__total` summed), `trackBuffer(cat, buf)`, `trackTexture(tex)`.
* Hooks (minimal, merge-safe): `gaia-render-native.js` +import +`memAttach({transport, writer, send})`; `material-map.js` +import, `memTex(t)` first line of `textureData`, `memBuf('pixelRead', out)` in `readPixels`; `vrm.js` +import, `memBuf('vrmBytes', b)` in `fetchVrmBytes`.
* NOT tracked: JS heap (no WebKit API: `performance.memory`/`measureUserAgentSpecificMemory` absent → `js_heap=none`; infer from `wc_MB` gap) · GLB/glTF raw bytes of three's `GLTFLoader`/`FileLoader` (no hook; only VRM bytes) · textures reachable only through TSL node graphs and not shipped via `textureData` · compressed-texture concatenated level buffer in texture desc · pending Promise/closure/string garbage (JSON, TSL sources/`nodeCache` packages, adapter Maps) · decoded-image size is an estimate · WebKit GPU/Networking processes (only WebContent + game-window) · render-host (Rust, inside `gw_MB`).

## §host-timeline (lane nt-timeline, 10-10) — host-side clock + sampler + per-op apply timing. UNVERIFIED at runtime (cargo check -p game-window only; no app run)
* Why: page main thread stalls 20–44 s → `[page:mem]` silent exactly then; `[apply] #7 16 MB total=5.0s` unnamed.
* **1. `[host:mem]`** — independent sampler, thread `gaia-hostmem`, NOT page-driven. `--host-mem-ms N` (env `GAIA_HOST_MEM_MS`, default 500, 0 = off). Needs no `--page-log`.
  * `[host:mem] t_ms=<since launch> wc_MB=<WebContent phys_footprint> gw_MB=<game-window phys_footprint>` (`n/a(<why>)` in place of a number on failure)
  * `[host:mem] t_ms=<..> wc_pid=<pid> gw_pid=<pid>` once per WebContent pid (re-printed if WebKit respawns it)
  * pid refresh = non-blocking `with_webview` post (`_webProcessIdentifier`); footprints = `proc_pid_rusage` syscalls on cached pid (`memfoot.rs`) → keeps ticking while page/WebContent stall. If host main thread blocks, pid stays last-known.
* **2. `t_ms=`** on every forwarded page line: `[page:<level>] t_ms=<N> <text>` (levels log/info/warn/error/uncaught/rejection/heartbeat) and `[page:mem] t_ms=<N> up=… |host …`. Same clock as `[host:mem]` (`memfoot::init_clock()` first in `main`). t_ms = host RECEIVE time → a stalled page delivers late; emit time is ≤ t_ms (the `up=` in `[page:mem]` is page time).
* **3. `[apply]` per-op breakdown** — `Host::time_ops` (gaia-render-host `lib.rs`; wall time per op kind inside `apply`, native only, off on wasm) read via `Host::last_apply_ops(top)`. `--apply-op-top N` (env `GAIA_APPLY_OP_TOP`, default 3, 0 = off → no per-command `Instant`). Dispatch = `Host::on_command` → `commands::dispatch` (all ops, hello/free incl.), so kinds = `commands::op_name`.
  * `[apply] #7 via=ws#1 16777216 B lock_wait=.. total=5.0s queued=.. report=.. ops=createTexture 4.2s x14 max=3.9s, createMesh 0.4s x200 max=40ms, render 0.1s x1 max=0.1s (cmds=215 ops_sum=4.8s other=0.2s)`
  * `ops` = top-N kinds by summed ms, `x` count, `max` slowest single command; `cmds` = commands finished in this apply; `ops_sum` = all kinds; `other` = apply wall − ops_sum (framer copy/buffering, report JSON). A command split across messages is timed in the message that completes it.
  * Logged only when `[apply]` is logged anyway (first 8, lock_wait > 50 ms, total > 100 ms; consts in `apply.rs`).
* Align: grep `t_ms=` over stderr → `[host:mem]` rows + `[page:*]` rows sort on one axis.
